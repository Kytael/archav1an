Executive summary

The codebase is a resumable, four-stage av1an boosting pipeline. It generates a VapourSynth script, runs a fast SVT-AV1 pass, scores per-frame quality (XPSNR or SSIMULACRA2), builds per-scene CRF zones, and runs the final encode. A batch supervisor daemon (encode-dash) spawns and adopts the batch process through a batch.json pid file, with split-host denoise over ssh+rsync+netstream.

The core batch machinery is carefully built and well-commented. Tests are genuinely strong: real subprocesses, a real HTTP daemon on loopback, corrupt-input fixtures, and bounded poll loops. No shell=True in the dispatch layer. The defects cluster in four areas: the pid-file liveness protocol (pid reuse and a non-atomic claim write), the HTTP body reader (negative Content-Length), a handful of real logic bugs in the main pipeline (fssimu2 result always discarded, dead _hr flag), and unchecked subprocess exit codes in shell scripts and one benchmark tool.

Critical findings

CriticalPid-reuse poisons the pid-file liveness protocolC1
encode_dash/supervisor.py:133 (adopt), 154 (start) · encode_dash/model.py:196,202 (batch), 244 (lane) · archive-batch.py:647-648

Every liveness decision treats "os.kill(pid, 0) succeeds" as "the batch runs", with no process-identity check. started_at is written (supervisor.py:120) but never compared. On a host that shells out ffmpeg/ffprobe constantly, a crashed batch's pid is recycled by the kernel: start() raises AlreadyRunning forever with no UI recovery, adopt() claims an unrelated process as the batch, and model._batch reports encode_batch_up=1 so the EncodeBatchDown alert never fires.

Fix: compare /proc/<pid>/stat field 22 (starttime) against the value captured at spawn/claim time; on mismatch, treat the file as stale, clear it, and proceed.

CriticalNegative Content-Length bypasses the body capC2
encode_dash/server.py:387-394

int("-1") parses, -1 > MAX_BODY is false, and self.rfile.read(-1) drains the whole connection until EOF. An unauthenticated tailnet peer can stream unbounded bytes into the daemon. There is also no socket timeout on the ThreadingHTTPServer and no thread cap, so a peer that declares a length and then stalls holds one thread forever.

Fix: reject length < 0, read exactly length bytes, and set a connection read timeout.

Main pipeline — Auto-Boost-Av1an.py

ImportantVS-ZIP fallback runs unconditionally and discards the fssimu2 resultI1
Auto-Boost-Av1an.py:1337-1396

After a successful fssimu2 run (metric_calculated = True at 1338) there is no early return, so the code recomputes SSIMULACRA2 with VS-ZIP and overwrites ssimu2_log_file (1396). In --ssimu2 fssimu2 mode the fssimu2 worker results never drive the zone calculation. If the vszip plugin is missing, the fallback raises SystemExit(1) and kills the whole pipeline even after a successful fssimu2 run. Verified in the source.

Fix: guard the fallback with if not metric_calculated: or return after the fssimu2 block writes its log.

ImportantVPY staleness check covers only one settingI2
Auto-Boost-Av1an.py:578-582

The check only inspects the # convert= marker. Changing any other setting baked into the template (--denoise-scunet, --denoise-model, --denoise-rvrt, settings.txt downscale/kernel/target_res, autocrop) silently reuses the stale VPY. If --convert-to-YUV420P10 differs, the VPY is regenerated with different crop/denoise settings than produced the existing fast-pass MKV and metrics logs.

Fix: write a hash of every template-relevant argument into the marker and regenerate on mismatch.

Importantshell=True on Windows breaks paths and can inject commandsI3
Auto-Boost-Av1an.py:69, 1260-1268

subprocess.run(cmd, ..., shell=use_shell) uses shell=True on Windows. With a list argument subprocess joins it unquoted, so a source path containing spaces breaks, and shell metacharacters (&, |, ;) in a filename inject commands.

Fix: always pass the list with shell=False; subprocess quotes Windows list args correctly.

Important_hr is always False — SD CRF chosen on HD contentI4
Auto-Boost-Av1an.py:988

_hr = bool(globals().get("hr", False)) is always False: hr is never assigned at module scope (it is a local in get_file_info and the VPY exec writes src to the locals dict, not globals). So --no-boosting on 1080p+ content always picks the SD CRF. The boosting path is unaffected because the CRF comes from the scenes JSON.

Fix: compute HR from the VPY as fast_pass does at 872, or thread it through get_file_info.

MinorSIGTERM path waits forever on a stuck childM1
Auto-Boost-Av1an.py:948-951, 1017-1020

After os.killpg(proc.pid, SIGTERM), proc.wait() has no timeout; if av1an or its children ignore SIGTERM, Ctrl+C hangs the script.

Fix: wait(timeout=...) then escalate to SIGKILL.

MinorPAM temp files leak on worker crashM2
Auto-Boost-Av1an.py:1263-1283

PAM cleanup sits after the fssimu2 try/except, so a worker crash leaves ref_*.pam/dist_*.pam files accumulating in tmp_dir.

Fix: unlink in a finally.

MinorResume crashes on a half-written info cacheM3
Auto-Boost-Av1an.py:754-766, 846-850

The cached info_src.txt is read with fixed slices but written in two separate appends. A kill between them (or an empty file) makes resume raise an unhandled IndexError/ValueError instead of rescanning.

Fix: validate the cache (line count / int-parse) and rescan on failure.

MinorCRF parsed by fixed character slicingM4
Auto-Boost-Av1an.py:400-412

CRF is sliced out of --crf by fixed indices; --crf 100.25 mis-parses to 100.2, and the code silently mutates the global quality used by the final pass.

Fix: parse with a regex/split; do not overwrite quality from a fast-pass-only flag.

MinorDead code and unused return valuesM5
Auto-Boost-Av1an.py:746-780, 1130, 1821, 1857

get_file_info modes "enc"/"len" are never called; tried_vship is set but never read; width/height/fps return values are discarded at the call sites.

Fix: delete or actually use them.

MinorModel dir interpolated unescaped into VPY sourceM6
Auto-Boost-Av1an.py:570, 661, 740

denoise_model_dir is interpolated into the generated VPY unescaped; a Windows path with backslashes produces a broken or injected string.

Fix: escape via repr or json.dumps.

MinorUnvalidated int() casts on user argsM7
Auto-Boost-Av1an.py:281, 353, 361, 370

int() on --stage, --ssimu2-cpu-workers, --workers, --photon-noise raises a raw traceback instead of an argparse error.

MinorDuplicated CRF mapping and final-move blocksM8
Auto-Boost-Av1an.py:881-891, 989-999, 1590-1600, 1829-1841, 1866-1877

The quality-to-CRF mapping is duplicated three times with near-identical bodies — finding I4 exists precisely because the copies drifted. The final-output move block is also duplicated.

Dispatch layer — svtav1 / av1an / pipeline / encode-capacity

ImportantRemote teardown kill discards a finished encodeI5
svtav1-dispatch.py:422-436

If the remote TRT/VS teardown outlasts the 30s ssh_proc.wait() — the code's own comment notes this teardown lags the last frame — ssh_proc is killed and sys.exit(15) aborts the whole encode with "output is truncated", even though every frame already landed and the IVF is complete. It never muxes, so a finished encode is discarded.

Fix: only abort when the delivered frame count is actually short; treat a teardown kill as a warning.

Importantremote_root interpolated raw into remote shell and rsync-pathI6
svtav1-dispatch.py:379-403

remote_root goes raw into cd {remote_root} && ... exec {remote_cmd} and into --rsync-path, while every other value is shlex.quoted. A root containing a space breaks cd; shell metacharacters inject into the remote shell.

Fix: shlex.quote(remote_root) and quote remote_dir inside the rsync-path.

ImportantVideo-only source gets an audio pass and failsI7
av1an-dispatch.py:22-35, 219-220

get_audio_channels returns 2 for a video-only source (empty stdout → int("") ValueError), and the caller unconditionally injects -a -c:a libopus -b:a 128k, so an encode of a no-audio file fails in av1an's audio pass. The equivalent function in svtav1-dispatch.py was already fixed (498-500).

Fix: return 0 on empty output and skip the -a flag.

ImportantCtrl+C during a mux step does not stop the batchI8
pipeline.py:308-312, 362-366, 585-596

_interrupted is only checked after scene detection and dispatch. A Ctrl+C during the mkvmerge/ffmpeg mux steps fails that one file and the loop keeps encoding the rest.

Fix: check _interrupted in the main loop after every step.

ImportantBenchmark ignores decoder failuresI9
encode-capacity.py:309-335

The decoder's (p1/ffmpeg) exit code is never checked. If ffmpeg fails (corrupt clip, missing codec), the encoder finalizes a short stream and exits 0, and the run is reported as a successful N-frame encode at inflated fps — silently poisoning every phase of the measurement.

Fix: capture p1.returncode and treat nonzero as an error.

MinorBSVD thSAD swap misfires on explicit defaultM10
svtav1-dispatch.py:990-991

The BSVD+SMDegrain thSAD=150 swap triggers on any value equal to the 350 default, including an explicit --denoise-thsad 350, contradicting the comment.

Fix: track whether the flag was given.

MinorBroken ssh yields a traceback and a 300s stallM11
svtav1-dispatch.py:397-404

ssh_proc.stdin.write can raise BrokenPipeError uncaught when ssh dies immediately (connection refused), and a failed ssh leaves the local netstream receiver waiting its full 300s accept_timeout.

MinorTemp cleanup omissions and doc driftM12
svtav1-dispatch.py:1254-1261, 727 vs 775

Cleanup omits .ffindex, _remote.log, _netstream.log, and windowed _denoise.source.vpy. USAGE documents --bsvd-overlap default 16 but the code default is 32. Remote staging uses a shared Temp/_remote/{basename}, so same-named sources from different directories clobber each other.

Minordispatch.py auto-detect probe hangs; resume contradicts cleanupM13
dispatch.py:121-136 · pipeline.py:316-336

The non-420 auto-detect ffprobe has no timeout and swallows all exceptions, so a hung probe silently skips the documented YUV420P10 conversion. Hidden av1an working dirs are rmtreed right before dispatch is invoked with --resume, so resume can never pick up state. source.stat() raises uncaught if a file vanishes mid-run.

Minorencode-capacity children can hang foreverM14
encode-capacity.py:321-326, 418-421, 423-432, 502-507

No timeout on Popen/communicate for encoder or denoise phases; a hung child blocks the benchmark indefinitely (worst over ssh). A failed denoise phase with 0 frames is stored but never flagged. Discard.stop() doesn't join its thread before sink.bytes is read.

Encode dashboard daemon — encode_dash/*

Important_record_pid can clobber a live claimI10
encode_dash/supervisor.py:108-121

_record_pid is check-then-replace, not compare-and-swap. It reads batch.json, decides it is safe to write, then os.replaces unconditionally. The batch side's claim uses O_EXCL (archive-batch.py:639), the authoritative primitive. A batch started from a shell in the microseconds between the read and the replace wins the claim and then has its file overwritten with the daemon's pid. Both batches then believe they own the run — two schedulers over the same manifest.

Fix: after os.replace, re-read and confirm the file still names our pid; if it does not, kill our own spawn and let the winner stand.

Importantstatus() is dead code; the spawn-to-claim window never reapsI11
encode_dash/supervisor.py:status() · encode-dash.py:89-97

Nothing calls status(); the comment claiming the supervisor's spawned pid is merged into the snapshot is false. The daemon never reaps its child except on a manual start(), so a finished batch stays a zombie for the daemon's whole lifetime, and the page shows "not running" for the entire spawn-to-_mark_claimed window.

Fix: call status() in _snapshot and merge, or drop the comment.

ImportantHeartbeat pid not type-checked before os.kill — a corrupt row 500s /metricsI12
encode_dash/model.py:200-203, 244

row.get("batch_pid") flows straight into _alive. A string value makes os.kill raise TypeError, which _alive does not catch (it only handles OSError). That takes out the Prometheus scrape — the exact failure this module was written to survive (its own comment at 182-187 demands the guard). The primary path at 188 type-checks correctly; the heartbeat fallback loop does not. Verified in the source.

Fix: mirror supervisor._pid_from_row in the heartbeat loop.

MinorSnapshot merge never happens; small protocol gapsM15
encode_dash/supervisor.py · model.py

Beyond the above, the adopt path never clears the _proc reference semantics completely and started_at is written but never consumed. These are consequences of C1 and I11 rather than independent defects.

Batch runner — archive-batch.py, scheduler, monitor

ImportantStale-claim takeover is a TOCTOU raceI13
archive-batch.py:654

_claim_run re-checks _alive(other), then _write_batch_file() does an unconditional os.replace. Two batches that both read a stale file and start concurrently both take over; the loser never re-checks under O_EXCL, so two schedulers run over the same manifest — the exact disaster the O_EXCL claim exists to prevent.

Fix: redo the takeover with os.open(BATCH_FILE, O_WRONLY|O_CREAT|O_EXCL) and, on FileExistsError, re-read and re-decide.

ImportantRetry duplicate-guard windowI14
archive_batch/scheduler.py:286-366

Between queue.get_nowait() and _in_flight.add(clip.src) a clip is in neither the queue nor _in_flight, so a retry control request in that window requeues a second copy. Two lanes then encode and publish to the same destination — precisely what the docstring at 97-101 claims the guard prevents.

Fix: register _in_flight before get_nowait (in the same lock) or gate retry on a flag set at take time.

Importantstart_trace leaks an fd on Popen failureI16
archive-batch.py:272-295

The CSV handle is opened before Popen; if the local or remote Popen (or the remote proc.stdin.write) raises, the except returns None without closing handle, leaking an fd per clip and leaving the CSV mid-write.

Fix: close in an except/finally.

Important"retry" records counted as failuresI17
archive-monitor.py:117-131

read_state counts every non-"done" record as a failure, so "retry" records (an instruction, not a result) inflate the failure count and appear in "recent failures".

Fix: elif status == "failed".

MinorXML values unescaped in tag.pyI18
tag.py:299-308

This one is arguably Important: encoder_name and encoding_settings are interpolated into XML unescaped. Any &/< in a batch flag produces malformed XML; mkvpropedit rejects the whole tag, so every file in the run fails to tag with a confusing error.

Fix: xml.sax.saxutils.escape the two values.

Minorcomp.py robustnessM16
comp.py:700-703, 1113, 1346

Bare str.replace instead of re.sub means suffix sanitization never runs (I15). get_suffixes raises IndexError when one filename is a prefix of the other. int(anime_episode_number) raises when no filename carries an episode number.

Audio, mux, streaming — opus.py, mux.py, netstream.py

MinorOrphaned encoder processes on stderr-read failureM17
opus.py:388-391, 500-506

When the stderr read loop raises (e.g. UnicodeDecodeError on text pipes), the except records the failure and calls task_done() but never kills or reaps the still-running ffmpeg/opusenc, leaving orphans competing for CPU across a large batch.

Fix: terminate proc in the except.

MinorMux temp files only removed on successM18
mux.py:323-324, 372-374

temp_mkv/timestamp_file are removed only on success; a CalledProcessError from Extract or Merge leaves them behind and the next run's -J globbing can pick up stale *_temp_no_video.mkv.

Minornetstream exits via traceback; opusenc presence check wrongM19
netstream.py:151-163, 199-203 · opus.py:122-124

USE_FFMPEG_FOR_OPUS tests not Path(OPUSENC_EXE).exists() where OPUSENC_EXE may be the bare name "opusenc", testing a relative file in CWD rather than the binary on PATH.

What was checked and found sound

No defect found in these areas — verified in source

  • Path traversal in server._static (server.py:108-136): decode-then-normpath, NUL reject, realpath + prefix check — correct.
  • CSRF gate (server.py:359-382): application/json forces an unsatisfiable preflight; the revision requirement on roster writes is coherent.
  • XSS in the dashboard UI: app.js escapes all interpolations; banners use textContent.
  • Atomicity of the normal-path writes: both _record_pid and _write_batch_file/_mark_claimed are tmp-then-os.replace; a killed batch leaves a dead-pid file that adopt() clears; an empty file from a mid-write kill reads as None.
  • No shell=True anywhere in the dispatch layer; ffprobe/frame-count verification and source-failure-as-fatal handling are defensive.
  • Test hygiene: no fixed ports (loopback bind to port 0), sockets bound before threads start, dead-pid fixtures spawn/reap real children, subprocesses SIGKILLed and reaped in finally, poll loops deadline-bounded.
  • Shell quoting: run scripts cd "$(dirname "$0")", use -print0 + read -d '' and quote everything; spaces in clip names are safe. setup.sh re-execs into bash under sudo sh and hands the prefix back on exit.

Method

Five parallel review passes, one per subsystem: main pipeline (Auto-Boost-Av1an.py); dispatch layer (svtav1-dispatch.py, dispatch.py, av1an-dispatch.py, pipeline.py, encode-capacity.py); dashboard daemon (encode_dash/* plus the cross-process pid-file contract with archive-batch.py); batch/mux/audio/stream tools; and tests + shell scripts. Every module was read in full and compiled with python3 -m py_compile (all pass). The top Critical and Important claims were re-verified directly in the source before inclusion. Test discovery verified with pytest --collect-only (384 tests). This is a static review; no code was executed except compilation and test collection.

Severity definitions: Critical = security boundary bypass or a permanent service failure (cannot restart). Important = wrong output, silent failure, or a race that can corrupt a run. Minor = robustness, cleanup, or test-quality issues with a clear fix.
